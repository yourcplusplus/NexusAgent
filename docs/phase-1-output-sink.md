# Phase 1:工具输出统一落盘

## 核心问题

Agent 跑得越久,对话记录越肥。每次跑命令、读文件,完整的 stdout、报错栈、搜索结果全都堆在 messages 里,token 账单线性上涨还只是小麻烦——真正头疼的是后面:上下文一压缩,这些细节全没了,只剩一句摘要。文件路径没了,想回看输出也没入口,等于前几轮的活儿白干。

## 机制

最初的方案很直接:输出太长就截断,超过预算把后面砍掉。但实测发现,报错栈的末尾——恰恰是最关键的 traceback——被砍掉了。头部只能看到"程序崩了","为什么崩"在尾部。所以改成落盘:完整输出写到 `.nexusagent/tool-outputs/` 下的 JSON 文件,Prompt 里只留头 30 行、尾 20 行,中间用一行「省略 X 行」带过,末尾附上文件路径。模型需要全文时按路径回读,不需要时也不浪费上下文;短输出(2KB 以内)原样通过,一分钱不多花。

只有行数限制还不够。单行本身可以很长——比如一整段被 dump 出来的 base64——行数很少,2KB 上限照样被顶爆。所以又加了一层字符预算兜底:裁完行数还超,就按字符数再裁一次。另一个坑是工具名,它是模型随手填的,得按白名单清洗一遍,不然名字里带个 `../` 就能把落盘文件写出工作区去。

还有个隐蔽的 bug 藏在记账层。搜索结果的 sources 列表,原来是从工具返回值里直接抽的——但返回值现在会被裁成摘要,列表摊平成一坨字符串,抽出来的 sources 就静默变空了,而且没有任何报错。修法是记账时从落盘前的原始结果里取,摘要只负责给人看。

## 文件

落盘逻辑收敛在一个入口:`tools/output_sink.py`。三个构造 ToolMessage 的地方(`nodes.py`、`code_agent.py`、`search_agent.py`)全部接入;`bash_tool.py` 原本自己有一套落盘,这次只把预览格式对齐成头尾,它的机制没动。测试 12 个,放 `tests/test_output_sink.py`。

## 测试

全量 167 个测试通过,其中 12 个是这次新写的。每个各盯一件事:短结果不落盘、100KB 的大输出能落能读、单行 40KB 的极端情况、grep 返回列表被摊平、工具名里夹路径穿越、落盘文件内容完整、随机 1000 种输出跑字符上界、5000 行的省略计数是否如实。

## 自查

随机测试抓出两个真 bug,都是写完代码自己没看出来的。第一个:「省略 N 行」的计数用的是探测时的假设值——界面显示省略 5000 行,实际省略 4950 行,在撒谎。第二个更隐蔽:裁行函数无条件放行第一行,单行超长时 2KB 上限照样被顶破——随机生成 300 个用例,45 个字符上界违规。两处修完,重跑 1000 个随机用例,0 违规。

## Phase 2 接管

这一版还有个尾巴:产物文件在磁盘上,但没有任何登记,压缩一来指针还是会丢。等 Phase 2 的白名单接手——`RuntimeState.touched_files` 补上之后,这里的产物自动进白名单,`output_sink` 本身不用再改。
